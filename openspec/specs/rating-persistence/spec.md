# rating-persistence Specification

## Purpose

定义评价如何跨会话保存、如何与磁盘上的照片重新对应（匹配模式与 key 的定义），以及评价在多个窗口之间如何保持一致。评价数据是用户的劳动成果，不可无故丢失。

## Requirements

### Requirement: 评价跨会话保留
系统 SHALL 在评价发生变化时立即持久化，并在之后任意一次打开包含同一照片的文件夹时恢复该评价。撤销评价 SHALL 同样被持久化。评价数据 SHALL 保存在应用自身的数据目录中，评价操作本身 SHALL NOT 在照片文件夹中创建或修改任何文件。

#### Scenario: 重启后恢复评价
- **WHEN** 用户评价若干照片后退出应用，再次打开同一文件夹
- **THEN** 之前的评价全部恢复

#### Scenario: 照片文件夹不被写入
- **WHEN** 用户只进行评价，不执行删除、改名或复制
- **THEN** 照片文件夹中的文件列表与文件内容保持不变

### Requirement: 匹配模式
系统 SHALL 提供 Hash 与 Path 两种匹配模式，用于决定评价以什么 key 存储与查找，默认为 Hash 模式。匹配模式的选择 SHALL 跨会话保留，修改后在下次打开文件夹时生效；已加载的文件夹在整个会话中 SHALL 保持加载时的匹配模式。恢复默认设置时 SHALL 回到 Hash 模式。

#### Scenario: 切换模式不影响当前会话
- **WHEN** 文件夹以 Hash 模式加载，用户随后在设置中切换为 Path 模式
- **THEN** 当前文件夹继续按 Hash 模式读写评价，直到下次打开文件夹

### Requirement: Hash 模式的 key 定义
在 Hash 模式下，照片的每个关联文件（全部 RAW 与输出文件）各自产生一个 key：取该文件的前 4 MB（文件不足 4 MB 时取整个文件）计算 SHA-256，表示为 64 位小写十六进制字符串。评价 SHALL 写入该照片全部关联文件的 key；读取时 SHALL 按照片内文件的顺序（见 photo-grouping）采用第一个存在评价的 key。

#### Scenario: 文件夹移动或重命名
- **WHEN** 用户评价后将整个文件夹移动到其他位置或改名，再重新打开
- **THEN** 评价全部恢复

#### Scenario: 只保留输出文件
- **WHEN** 照片评价时同时有 RAW 与输出文件，之后用户在应用外删除了 RAW 文件
- **THEN** 重新打开文件夹时，仅剩输出文件的该照片仍保留原评价

#### Scenario: 部分文件内容变化
- **WHEN** 评价后，照片的输出文件被重新导出（内容变化），RAW 文件未变
- **THEN** 重新打开文件夹时，该照片通过 RAW 文件的 key 恢复原评价

#### Scenario: 全部文件内容变化
- **WHEN** 评价后，照片所有关联文件的前 4 MB 内容都发生了变化
- **THEN** 重新打开文件夹时，该照片显示为未评价

#### Scenario: 多个文件都写入评价
- **WHEN** 照片包含 `DSC00001.ARW`、`DSC00001.DNG` 与 `DSC00001.HIF`，用户将其评价为合格，之后在应用外删除了 `DSC00001.ARW` 与 `DSC00001.HIF`
- **THEN** 重新打开文件夹时，仅剩 `DSC00001.DNG` 的该照片仍为合格

#### Scenario: 各文件的已存评价不一致
- **WHEN** 照片包含 `DSC00002.ARW` 与 `DSC00002.JPG`，`DSC00002.ARW` 的 key 存有合格评价，`DSC00002.JPG` 的 key 存有糟糕评价
- **THEN** 该照片显示为合格

### Requirement: Path 模式的 key 定义
在 Path 模式下，照片的 key 为其 RAW 文件（没有 RAW 时为输出文件）去掉扩展名后的绝对路径。Path 模式 SHALL NOT 读取文件内容来计算 key。

#### Scenario: 路径不变
- **WHEN** 以 Path 模式评价后重新打开同一位置的文件夹
- **THEN** 评价全部恢复

#### Scenario: 路径变化
- **WHEN** 以 Path 模式评价后，用户在应用外移动或重命名了文件夹
- **THEN** 重新打开文件夹时，照片显示为未评价

### Requirement: 两种模式的评价相互独立
Hash 模式与 Path 模式下产生的评价 SHALL 同时保留、互不覆盖。在一种模式下给出的评价 SHALL NOT 出现在另一种模式下。

#### Scenario: 切换模式后评价不可见
- **WHEN** 用户以 Hash 模式评价了某文件夹，之后切换为 Path 模式并重新打开该文件夹
- **THEN** 照片显示为未评价

#### Scenario: 切换回原模式
- **WHEN** 用户再切换回 Hash 模式并重新打开该文件夹
- **THEN** 之前以 Hash 模式给出的评价全部恢复

### Requirement: 多窗口评价同步
当同一照片在多个窗口中以相同匹配模式打开时，任一窗口中的评价变化 SHALL 立即反映到其他窗口。

#### Scenario: 另一窗口中的评价
- **WHEN** 两个窗口打开了同一文件夹，用户在窗口 A 中将某照片评价为合格
- **THEN** 窗口 B 中该照片也立即显示为合格，进度同步更新

### Requirement: 清除全部评价
系统 SHALL 提供清除全部已存评价的操作，覆盖所有文件夹与两种匹配模式。执行前 SHALL 要求用户确认，并提示该操作不可撤销。清除后所有已打开窗口中的照片 SHALL 立即显示为未评价。

#### Scenario: 确认清除
- **WHEN** 用户执行清除全部评价并确认
- **THEN** 所有已存评价被删除，已打开窗口中的照片全部变为未评价

#### Scenario: 取消清除
- **WHEN** 用户执行清除全部评价但在确认时取消
- **THEN** 评价保持不变

### Requirement: 清除当前文件夹评价
系统 SHALL 提供清除当前文件夹评价的操作，当前文件夹指最近一个处于活动状态的照片窗口所打开的文件夹。执行前 SHALL 要求用户确认并显示该文件夹名称。该窗口没有已加载的照片时，该操作 SHALL 不可用。

#### Scenario: 只清除当前文件夹
- **WHEN** 用户在文件夹 A 的窗口处于活动状态时执行清除当前文件夹评价并确认
- **THEN** 文件夹 A 中照片的评价被删除，其他文件夹的评价保持不变

#### Scenario: 未加载文件夹
- **WHEN** 最近处于活动状态的照片窗口尚未加载照片
- **THEN** 清除当前文件夹评价不可用
